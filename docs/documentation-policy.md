# 文档语言与发布状态规范

## 语言与适用范围

现行维护文档（Living docs）的标题、正文和说明默认使用简体中文。维护者与 Agent 修改文档均须遵守本规范，只做必要整理，不借语言调整改变技术结论。

项目名、Runtime、API、CLI 等技术名词可保留英文。文件名、路径、字段、命令、状态值、错误码、API route、代码和精确日志保持原文，不机械翻译。Steam 精确日志 `SV:  Connection to Steam servers successful.` 中的两个空格也不能改变。

LICENSE、第三方许可证、PATENTS 和版权声明保留上游原文。LICENSING.md 的既有授权语义不因语言整理而重写。

docs/validation 中的具体记录是历史时点证据，保留当时语言、版本、失败、候选和待验证状态，不批量翻译或改写。该目录 README 是现行导航。docs/decisions.md 保留历史决策语境，不作为当前部署状态的来源。

## 当前状态与历史引用

当前发布版本的机器来源是 tools/package/VERSION；现行文档中的当前稳定版本声明须与之对应。正式版本不能仍被描述为候选或未发布。历史版本对照、固定 tag 链接、旧版资产未变的说明可以保留，不能见到旧版本号就批量替换。

后续准备候选时应明确区分候选版本和已经发布的稳定版本；如需表达两种身份，应先调整检查契约和测试，而不是关闭检查。main 的文档维护不改变历史 tag、Release 页面或资产。

## 自动检查与人工审阅

在源码仓库根目录运行：

```text
python tools/check_docs.py
python tools/check_docs_test.py
```

提交文档及发布前必须通过检查；Linux CI 执行同样命令，失败阻断 CI。新增现行文档须评估是否加入工具中的显式清单。

工具读取 VERSION，检查明确的当前版本声明、正式版本的候选状态残留，以及每份现行文档是否至少有 20 个正文中文字符。代码块、引用块和链接目标不用于语言计数；历史验证正文与法律文本不进入清单。20 字只是防止整篇英文退化的最低门槛，不证明中文占比或翻译质量。规则不是自然语言理解器，人工审阅仍须确认语境、链接、发布事实和技术语义。

错误示例应放在代码块或引用块中，避免被当成真实状态声明。不要通过吞错、削弱门槛或把真实当前说明伪装成引用来绕过检查。
