# M2-06 整机重启验收步骤（未执行）

本文是 [M2](m2.md) 尚未执行的验收流程，不是通过记录。Windows 10 与 Ubuntu 24 分别执行；管理端重启、模拟 boot ID、辅助进程测试或编译不能替代真实操作系统重启。普通重启也不等同断电测试。

## 环境与证据

只使用明确允许重启的隔离机器。执行前核对主机身份、操作系统版本、CPU/内存/磁盘、当前进程与服务、游戏安装、可写目录及端口预约；不得使用生产主机。记录本次允许影响的目录、进程与重启范围。新机器使用独立 SSH 身份与已核验主机密钥，不复制生产运行记录、不复用生产 data-dir。

准备相同提交的核心、游戏及依赖、用户提供的原始 VPK。记录二进制/地图指纹和游戏版本；地图的客户端名称与资源匹配。核心不负责安装或更新游戏。新环境先完成 check、真实启动、客户端进房和正常回收，确认运行前提后再进行重启用例。

管理端不设置自动启动，测试游戏也不能由其他启动器或服务自动拉起。使用普通测试用户、独立 data-dir、独立生成cfg及日志目录；明确收集并保留重启前后状态与操作结果，不修改原记录来制造旧PID冲突。

## 实际操作与判定

1. 创建独立测试实例并等待就绪，客户端确认进入。记录实例ID、创建幂等键、操作ID、代次、完整进程身份、配置快照、日志指纹和监听。另保存管理端离线的基线副本作为证据，不覆盖活动目录。
2. 正常退出管理端，确认游戏仍存活；保存最后的游戏身份。执行已授权的隔离机操作系统重启，保存重启前后系统启动标识/时间。不要先 stop 回收该实例，否则无法验收残留活动记录。
3. 系统回来后，先只读检查：原游戏不应重新出现，核心不得由未声明的自启动项运行，原 data-dir 必须保留。保存当前进程与监听清单，不能把旧PID数字视作身份。
4. 使用同一用户、同一 data-dir 启动核心。查询 list/status/operation，确认旧实例ID、快照、代次及历史操作仍在；当前状态不得沿用旧 ready，不得产生新一代或新游戏进程。旧PID不存在时应反映已退出；若被无关进程占用或身份不可核验，则应拒绝接管并保留 unknown/诊断。
5. 使用原模板路径、原端口和原创建键重试，必须返回原实例/操作，不创建替代房间。复核游戏进程与代次没有增加。不能通过换创建键绕过未确认的残留。
6. 显式 stop 原实例，核对确认退出后才能回收。若身份不可确认，应保持失败和分配，保留证据，不手工杀旧PID或删记录继续。核对无关进程未被控制、生成文件按归属清理，原VPK/模板和历史日志保留。
7. 旧实例成功回收后，以新意图创建新实例，实际进房并正常停止。保存操作终态、列表、端口及文件回收证据，最后停止本轮管理端。

记录每一步命令、返回值和时间；原始记录留在私有验收目录，公开报告仅保留脱敏结论。若真实重启未自然产生PID复用，明确记录“未观察到实际PID复用”；既有身份冲突辅助测试单独列示，不能声称实测覆盖了该场景。任何失败均保留，不以删状态、重建 data-dir 或修改校验和绕过。
