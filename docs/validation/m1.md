## M1-02 验证（2026-09-19）

Windows：Go 1.27.1，`go test -p 2 ./...`、`go vet ./...` 通过。Ubuntu 24.04.5：以普通游戏用户执行交叉编译后的配置测试二进制，`-test.v -test.timeout=60s` 全部通过；这是本机执行结果，不只交叉编译。测试不启动专服。

覆盖重复/未知/大小写错误 JSON 字段、版本、大小与 null 边界、绝对路径和文件类型、未知/残缺占位符、参数与 cfg 不同转义上下文、带空格路径、ASCII 日志路径、超时/就绪规则、源配置不变。check 的 stdout 是一份 JSON，静态检查失败不会生成运行目录；它不验证地图可加载或端口可用。

真实 Go 专服生命周期、客户端进房及阶段出口均未验证，不能据此进入 M2。

## M1-03 验证（2026-09-19）

记录模块保存规范化模板、显式端口、随机实例/操作 ID、各代参数与 cfg/log 路径；生成 cfg 独占创建并保留内容指纹，清理核对实例、代次、路径及内容。日志、快照和操作历史不随 cfg 清理删除。创建键重试优先返回原记录，不重新读取修改后的源模板。

Windows 和 Ubuntu 普通用户原生测试通过：同模板双记录、端口预约/实际 TCP 与 UDP 冲突、幂等冲突、修改源模板后的快照复用、代次隔离、外来/已改 cfg 不被删除、清理重试、历史保留、损坏/版本记录拒绝。

首轮测试确实失败：Windows 通配绑定漏检回环占用，缺失 keys 和 null run 被接受，清理接受非 Store 持有的实例。已分别修复独占 socket、零值解码及记录/归属验证，保留失败测试并双平台复测通过。测试可触发 Windows 临时测试程序的防火墙提示；无需放行外部连接。

当前只有文件级保存与基本重试；完整崩溃持久化、互斥与恢复仍分别由 M1-05/M2 验证，不宣称已完成恢复验收。
