## M1-02 验证（2026-09-19）

Windows：Go 1.27.1，`go test -p 2 ./...`、`go vet ./...` 通过。Ubuntu 24.04.5：以普通游戏用户执行交叉编译后的配置测试二进制，`-test.v -test.timeout=60s` 全部通过；这是本机执行结果，不只交叉编译。测试不启动专服。

覆盖重复/未知/大小写错误 JSON 字段、版本、大小与 null 边界、绝对路径和文件类型、未知/残缺占位符、参数与 cfg 不同转义上下文、带空格路径、ASCII 日志路径、超时/就绪规则、源配置不变。check 的 stdout 是一份 JSON，静态检查失败不会生成运行目录；它不验证地图可加载或端口可用。

真实 Go 专服生命周期、客户端进房及阶段出口均未验证，不能据此进入 M2。

## M1-03 验证（2026-09-19）

记录模块保存规范化模板、显式端口、随机实例/操作 ID、各代参数与 cfg/log 路径；生成 cfg 独占创建并保留内容指纹，清理核对实例、代次、路径及内容。日志、快照和操作历史不随 cfg 清理删除。创建键重试优先返回原记录，不重新读取修改后的源模板。

Windows 和 Ubuntu 普通用户原生测试通过：同模板双记录、端口预约/实际 TCP 与 UDP 冲突、幂等冲突、修改源模板后的快照复用、代次隔离、外来/已改 cfg 不被删除、清理重试、历史保留、损坏/版本记录拒绝。

首轮测试确实失败：Windows 通配绑定漏检回环占用，缺失 keys 和 null run 被接受，清理接受非 Store 持有的实例。已分别修复独占 socket、零值解码及记录/归属验证，保留失败测试并双平台复测通过。测试可触发 Windows 临时测试程序的防火墙提示；无需放行外部连接。

当前只有文件级保存与基本重试；完整崩溃持久化、互斥与恢复仍分别由 M1-05/M2 验证，不宣称已完成恢复验收。

## M1-04 原生进程验证（2026-09-19）

Windows：持有进程句柄后校验精确创建时间/程序路径；独立辅助进程核验控制台归属后仅发送 quit；强制停止使用该句柄。Linux：setsid、独立 FIFO、boot ID/start ticks/exe/argv/FIFO inode 与 pidfd，拒绝 PID-only 信号；按设备号/inode 清理输入 FIFO。

双平台辅助进程实测身份冲突拒绝、优雅退出/强制停止、原生套接字归属、父进程结束后输出持续写入；Windows 另测父进程非零退出。读取仅针对当前代独占日志，失败信号优先，中文 tail 保真。Linux 首轮出现退出竞态（/proc 信息消失先于观察到 pidfd 退出）；仅在同一 pidfd 上有界重查，保留失败测试后原生三轮通过。

以上测试没有启动 Dota，也不能替代 M1-07。真实引擎的加载超时、停止、重启和客户端进房仍须独立执行。

## M1-05/06 整合验证（2026-09-19）

Windows 宿主与 Ubuntu 普通用户执行辅助进程整合：创建→就绪→源模板修改→快照重启→读取中文日志→停止→历史查询、幂等重试、移出活动列表及端口释放均通过。另测早退、超时、加载中停止、排队重启被停止中止、历史成功后异常退出、清理失败重试、身份不明不回收、未知 ID 与无效模板、三处保存故障不误报成功、Close 返回后无后台写入。排队取消测试不能替代真实重启中停止，后续单独验收。

IPC：双平台往返、第二管理端拒绝、请求取消后已受理任务继续、报文大小、端点替换不误删、停接收后仍持锁直至显式 Close。Windows 实际 AnonymousToken 访问拒绝；Ubuntu 实际 UID65534 子进程访问拒绝（普通用户测试明确 skip，此项另以 root 在自建临时目录单跑通过，不创建账号）。跨 UID 首轮测试因 os.IsPermission 不识别 net.OpError 包装误报失败，改 errors.Is 后实际 EACCES 得到确认。

数据根和接口目录的权限均核验；已有不安全目录被拒且原权限不变。Windows 严格 ACL 测试在沙箱受限令牌下被拒，因此按正常审批在宿主执行，未放宽 ACL。真实 CLI/命名管道 smoke 验证空 list、第二 serve 拒绝和未知 status；只结束该测试创建的无实例管理端。

审查中发现并修复 Linux 监听协议枚举与核心不一致、Close 提前释放写锁、保存失败错误状态、历史输入清理记账。完整 M2 崩溃恢复及 M3 存储上限仍未实现/验收。
