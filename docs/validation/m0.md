# M0 运行验证报告

M0 运行基线已完成。结果限定于下列平台、引擎构建和一个测试地图，不等于正式管理核心完成，也不保证任意地图兼容。

## 环境与方法

验证日期：2026-09-18。Windows 10 Pro 22H2（build 19045）与 Ubuntu 24.04.5（Linux 6.8），均为 amd64。Dota Client/ServerVersion 6933，SourceRevision 10999813；同一份 OMG AI 4+3 VPK 的 n7 地图用于两平台，上传及实际挂载文件均经 SHA256 核验。Go 工具链为 1.27.1。

Windows 通过回环连接本机专服；Ubuntu 通过域名和 NAT UDP 映射连接。Ubuntu 以普通游戏用户运行引擎，在独立资源受限单元中只读使用共享安装，并隔离 cfg、addon、HOME 和日志。未修改线上服务、共享地图或网络规则。原始配置及证据留在本地，不发布游戏资源和玩家日志。

## 关键发现与失败对照

- **资源定位：**服务器正确加载 VPK 不代表客户端也能加载它。将 Linux 绝对路径传给 Windows 客户端的尝试出现路径警告并崩溃，未达到完整进房。改用两端独有的同名 VPK、核验相同字节后两次成功。未证明失败时究竟读取了哪个历史资源。
- **地图与就绪：**解包后的地图曾达到 ss_active，但主脚本失败；因此该信号不能单独判就绪。最终成功使用原始 VPK，没有修补地图代码。解包脚本错误根因未定。
- **隔离安装：**仅放测试 cfg 的私有目录曾遮蔽引擎默认配置而崩溃。补齐明确的 stock 配置副本后解决；不能复制生产房间启动 cfg 来代替独立准备。
- **日志：**不可写日志时引擎仍可能存活，stdout 不足以替代完整引擎日志。必须以实际运行用户预检日志写入。中文路径失败与中文内容编码是不同问题；当前限制只针对引擎日志路径。
- **端口：**引擎同时绑定同号 UDP/TCP，另有动态回环 TCP 监听及出站临时端口。指定回环 IP 不保证 UDP 仅监听回环。本次仅映射公网 UDP 即可进房，不推广为所有场景都不需要 TCP。
- **实验自身的失败：**一次 Windows ACL 注入失败后脚本仍继续启动了测试进程，已按身份停止，修正为设置失败立即退出后重测；一次管道探针同步等待未返回，改为有界异步读写后通过。失败尝试不计为通过。

## 复验流程

1. 确认安装、资源哈希、客户端资源、可写目录、可用端口和保护对象，建立独立运行目录；不使用在用房间测试。
2. 记录完整 argv、实际 cfg、唯一运行标记与身份；日志直接写入本代文件。
3. 采集实际 TCP/UDP 监听、出站连接和子进程；检查加载及地图级信号，再由真实客户端进房。
4. 核验身份后停止，确认进程、子进程和端口退出，再以同配置启动下一代并再次进房。
5. 分别验证工具正常退出、异常退出和身份未落盘窗口；不明确的残留阻止重复派生，身份不匹配必须拒绝控制。
6. 在隔离目录注入端口冲突、不可写日志、无效地图与退出超时，保留失败诊断；仅清理有归属且内容匹配的生成文件。

[公开工具](../../tools/m0/README.md) 提供只读采集和 Windows 实验探针；本次绑定特定云主机的隔离脚本不作为通用部署工具发布。Ubuntu 复验需按上述隔离与身份约束在自己的环境重新准备，不能直接套用历史配置。
