## 恢复决策

数据格式2独立于模板/协议版本。增加校验和、操作阶段、启动尝试标记与绝对就绪截止时间；不静默转换格式1的实验数据，遇到旧版明确拒绝且保留文件。原 M1 测试已回收，证据完整保留；M2 使用新目录。

每次进程启动前持久化唯一代次、最终参数、cfg指纹和启动意图。管理端恢复不新建游戏进程：已核验原进程可继续本代就绪观察；截止时间包含离线时间，不重置超时。只有启动意图而没有可恢复代次的创建/重启，结束为 INTERRUPTED，保留 ID、分配和诊断，调用方可显式 stop 后用新意图创建。旧代仍存活不能算重启完成。

已受理 stop 中断后，在身份或持久化的退出结果确认后继续停止/清理。完成结果与当前状态分开，历史成功不会被改写；清理故障保留记录，可再次 stop。已持久化的确认退出结果允许按文件指纹清理，不重新使用可能已复用的旧 PID。

身份未落盘时按精确程序、完整参数、时间下界发现候选；Linux还核验当前用户及本代FIFO设备/inode。只有唯一候选且原生身份再次核验通过才认领。任何无法检查的潜在目标或多个候选保留 unknown，不信任端口/PID/名称。Linux 时间下界使用意图时间取整秒再减1秒，容纳系统时间与tick精度；这不是单独的归属依据。

创建键作用域仍为同一 data-dir，包含规范化模板路径和显式端口。重试先查原记录，不重新读已修改或删除的模板；同键不同参数明确冲突。M2 不过期删除键，M3 将与历史保留政策统一，旧键在保留期内不得产生新实例。

## 证据与限制

2026-09-19，基于实现提交 `0ebfd72` 完成 Windows 真实 Dota 验证：管理端异常退出后恢复同一实例、原进程及第1代，再正常退出；管理端离线时用户确认正常进入地图。引擎日志由42917增至85198字节，并新增完整签入记录。此前空闲观察日志没有增长，未把空闲观察当作日志持续写入证据。再次启动管理端后恢复原实例，显式 stop 成功，退出确认且 forced=false，临时cfg移除、活动列表为空、游戏端口释放；最后管理端正常退出0。原始证据仅保留本地，公开记录不包含玩家信息。

同日 Ubuntu 已完成管理端异常退出、重新接管原实例及正常退出；管理端离线时用户确认正常进入地图，日志43186→85535字节并出现完整签入。第三次管理端启动仍恢复原实例、原PID及第1代；同键重试返回原创建操作和实例。最终 stop 成功，forced=false，活动列表为空，生成cfg与FIFO已清理、游戏端口释放；三个独立测试单位均已停止。现有生产房间未操作。

Ubuntu实机测试采用独立目录、普通用户和私有挂载视图；为避免测试单位在管理端被杀后连带停止游戏，专用 systemd 单位设置 RemainAfterExit=yes、SuccessExitStatus=SIGKILL。这是本轮故障注入环境设置，不是核心运行依赖，不改变生产服务。

用户正在准备可重启的 Ubuntu 24 隔离测试机，需要用户参与的测试等其返回。Windows已于2026-09-20在专用虚拟机完成真实整机重启验收。准备流程见 [整机重启验收步骤](m2-reboot.md)，Windows证据见该文末结果；Ubuntu仍未执行，不能从管理端退出结果推断整机重启结果。

实现、辅助进程验证和真实引擎验收分别记录。进程字段或boot ID的模拟变化只能验证拒绝逻辑，不能代替整机重启。M2-06的Ubuntu验收仍缺测试环境，当前不得宣布M2整体通过。用户随后明确授权带该待验收项继续M3/M4开发；最终验收不变，补测失败须回归受影响项。

Windows 全套自动测试/vet通过；Ubuntu普通用户原生 records、engine、core 全套通过，原始输出保留于忽略目录。发现模块拒绝多个精确候选；清理测试将旧PID指向测试自身，验证确认退出后只按FIFO指纹清理且不会控制该PID。恢复测试覆盖管理进程真正 Exit(73) 的启动前、身份保存前和退出记录保存后窗口；这是有界辅助进程，不是 Dota 实机验收。

格式2使用 store.marker 和完整性校验，缺失 state/marker、有效JSON但错误关联、未知枚举、重复预约、错误代次路径或参数均拒绝，不初始化为空来掩盖丢失。首个初始化标记成功而状态未能发布时同样要求诊断。校验和只检测意外损坏，不防范有相同用户权限的人主动重写数据。

Linux使用文件同步、rename和目录fsync；Windows文件同步后使用 [MoveFileEx写透](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw)，不宣称具有普通用户可用的目录fsync等价能力。Windows发现使用经过本机测试的NT命令行查询；该接口[可能变化](https://learn.microsoft.com/en-us/windows/win32/api/winternl/nf-winternl-ntqueryinformationprocess)，不可用时保留未知，不回退到PID认领。
