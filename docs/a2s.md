# A2S 与协议进房

## 本地管理 API 与 A2S

d2core 本地 API 通过 Windows Named Pipe 或 Linux Unix socket 提供同用户 create、status、operation、restart、stop、logs 等实例生命周期管理。它不是公网远程 API、Steam 查询协议或玩家进房协议，契约见 [本地协议](local-api.md)。

A2S 属于 Dota / Steam 游戏服务器查询生态，一个实际用途是为 Steam / 蒸汽平台协议一键进房提供需要的服务端查询能力。它不是 d2core 管理 API、平台 Node API、玩家身份系统或公网远程管理接口。

## 独立 A2S 配置工具

```text
d2core a2s enable --dota-dir <游戏安装绝对路径> --json
```

仅检查并合并 game/dota/gameinfo.gi 的 GameInfo/GMS/Advertise 1。普通 create/restart 不调用此工具，不自动改变 VAC 或 gameinfo。工具不需要管理端运行。

返回 result.status：inserted（已插入并读回核验）、already_configured（已存在相同值，无新备份/改写）、conflict（原值不同、重复结构、锁或并发变化）、error（路径、权限或读写失败）。失败退出1，参数用法错误退出2；error对象提供原因。result.path为目标，实际准备备份时返回result.backup。

修改前将原始字节保存为同目录 gameinfo.gi.d2core-<原内容SHA256>.bak，独占创建并同步；同名备份必须逐字节匹配，否则拒绝。仅插入必要节点，保留原注释、换行与其他内容。UTF-8（允许BOM）、最大4MiB，结构歧义、指令/条件语法或非普通文件拒绝，不猜测修改位置；路径含链接时使用解析后的明确安装位置。

同目录独占锁协调本工具的并发执行；写临时文件并同步后，再核验源文件身份与内容未变，替换并读回核验。锁不替代系统级配置变更管理：执行期间不要同时运行安装更新或其他编辑器写入gameinfo。无法承诺阻止不遵守工具锁的外部程序在最终检查后写入；读回发现差异会报告冲突并保留备份。异常退出留下的锁不会自动删除，应先确认没有仍在执行的工具再人工处理。

失败不代表必然未写入：替换后验证或同步失败时保留备份并报告error，先检查文件，不盲目覆盖还原。需要回滚时先停止使用该配置的测试实例，核对当前文件及备份归属，再恢复已核验备份。Linux同步文件和目录；Windows使用写透替换，不以此宣称整机断电验收通过。

配置成功不代表运行中的引擎已生效。必须重启对应隔离测试服，并单独执行A2S查询；进房/就绪验证仍独立进行。已知同机共用客户端安装修改gameinfo可能影响安全握手，测试使用独立副本/挂载，不自动修改玩家共用安装或生产配置。

当前已通过双平台原生文件测试：内容保留、幂等、备份、结构/值冲突、并发编辑检测、原生写权限拒绝、链接拒绝、写入失败各阶段。Ubuntu 隔离配置下真实 A2S_INFO 查询已通过；Windows 早先独立路径试验查询超时，后在独立虚拟机安装上实际挑战及 A2S_INFO 查询通过，详见 [M4 记录](https://github.com/L4C99/dota2-arcade-dedicated-core/blob/v0.1.1/docs/validation/m4.md)。


## 三类进房方式与证据边界

以下兼容性说明依据项目使用者提供的实际测试观察整理；本轮仅整理文档，未新增 URI 或 A2S 实验。既有双平台 A2S 查询验证见上方历史记录。完整入口格式由项目使用者补充确认为：

```text
steam://connect/<IP>:<PORT>
steamchina://connect/<IP>:<PORT>
```

将 `<IP>`、`<PORT>` 替换为玩家实际可达的 IP 和端口，不保留尖括号。例如 `steam://connect/203.0.113.10:27017` 或 `steamchina://connect/203.0.113.10:27017`；这里使用文档示例 IP，须换成实际部署值。可作为协议链接打开，或复制完整 URI 到 Windows Win + R 执行。格式确认不等于所有客户端、域名或 NAT 拓扑均已验证。

| 方式 | IP | 域名 | 外部映射端口与本机游戏端口不同 | 依赖 A2S |
| --- | --- | --- | --- | --- |
| Dota 控制台 `connect` | 已验证 | 已验证可解析域名 | 可使用实际公网映射端口，仍需网络可达 | 否 |
| `steam://` | 已验证方式使用 IP | 当前不作为已验证能力 | 实测观察到可能失败 | 是 |
| `steamchina://` | 独立兼容验证未记录 | 未验证 | 实测观察到可能失败 | 是 |

`connect <host>:<port>` 是基础兜底方式，不依赖 d2core 的 A2S 配置。Steam 协议当前验证使用 IP，不应把普通 connect 的域名直接当作 URI host 的等价替代；这不是“协议标准永久禁止域名”的结论。`steamchina://` 是蒸汽平台侧入口，其完整格式如上；独立 IP/域名兼容行为不能从 Steam 自动推导。

### 服务端查询与客户端唤起分别验收

A2S 查询正常只是服务端前提，不保证协议链接能在任意浏览器、Windows 环境或 NAT 拓扑下一键进房。`a2s enable` 成功也不代表运行中的引擎已生效，须按前文重启并独立查询。d2core 不提供 URI 生成器，也不在本地 API 中代办玩家进房。

实测观察到：Steam 尚未运行时，浏览器点击 `steam://` 或 `steamchina://` 链接尝试冷启动 Steam / Dota，在部分 Windows 环境中可能启动失败。现象与协议处理器启动上下文/进程工作目录有关，尚不能认定工作目录是唯一根因。

已测试的规避方式是先正常启动 Steam 再点击链接，或复制已有的完整协议 URI，通过 Windows **Win + R** 执行。协议链接点击失败不等于 A2S 一定失败，也不等于服务器一定故障；继续用 Dota 控制台 `connect <host>:<port>` 验证。

### 本机游戏端口与公网映射端口

- `status.port` 是实例实际使用的本机游戏端口，不是公网端口或独立 query port 字段。
- public / mapped port 是玩家从公网实际访问的端口，由部署方提供。d2core 不推导公网地址、配置 NAT、映射、防火墙或 DNS；此文不假设查询端口与游戏端口存在未经验证的固定偏移关系。
- 例如本机游戏端口为 `27017`、公网映射为 `30017 -> 27017`，控制台可以使用 `connect public.example.com:30017`（文档示例域名），前提是映射与网络确实可达。

启用 A2S 后，实测观察到游戏监听端口与公网映射端口不同时，Steam / steamchina 类一键入口可能失败，不能视为已可靠支持任意端口转换。需要依赖一键进房时，保守建议保持公网游戏端口与 Dota 实际游戏端口相同，尽量采用 1:1 端口映射；这是项目实测兼容建议，**不是已证明的 Steam 官方协议要求，也不是成功保证**。

必须使用不同外部端口时，应分别用真实客户端验证所提供的协议入口，不默认标记可靠支持；保留 `connect <public-host>:<public-port>`。首次部署及网络变化后的分项验收见 [操作说明](operations.md#真实进房与网络验收)。
