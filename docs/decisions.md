# 技术决策

本文保留研发阶段的设计选择与当时验证状态，包含 M0—M4 / CJ 历史编号，不代表当前部署状态。当前规格与操作以 [本地协议](local-api.md)、[操作说明](operations.md) 为准；历史证据见 [验证索引](validation/README.md)。

## 工具链与实现边界

开发工具链为 Go 1.27.1。Windows 本地管道采用微软官方 [go-winio v0.6.2](https://github.com/microsoft/go-winio/releases/tag/v0.6.2)，系统 API 使用 golang.org/x/sys v0.10.0；版本及校验和锁定在 go.mod/go.sum。避免自行实现易出错的重叠 IO 取消与 deadline；已核对库源码设置 FILE_PIPE_REJECT_REMOTE_CLIENTS，并执行真实匿名令牌拒绝测试。PowerShell/Python 仅用于开发与隔离验收，不是最终使用者的安装前提。

`m0-inspect` 只读取显式路径、解析链接并计算指纹，不启动引擎，也不验证写权限、资源冻结或任意 cfg 引用。静态检查成功不代表地图可加载。

## 进程、恢复与通信

| 方面 | 选型 / 约束 | 后续验证 |
| --- | --- | --- |
| Windows 身份 | 持有 OS 进程句柄后检查程序路径和精确创建时间 | 正式 Go 适配、重启后旧记录与身份冲突 |
| Windows 停止 | 独立辅助进程确认独占控制台后发送 quit；强制停止使用核验后的句柄 | 控制台不可用、完整子进程处理；不能用管理端关闭即杀游戏的 Job 选项 |
| Linux 身份与停止 | boot ID、启动 ticks、路径和 argv 核验；FIFO quit；pidfd 强制信号 | 正式 Go 启动/恢复适配；不退化为只按 PID 终止 |
| 本地传输 | Windows 当前用户 ACL 命名管道；Linux 私有目录 Unix socket，校验 peer UID | 跨用户拒绝、远程管道拒绝、端点抢占、超时及长路径 |
| 管理端离线日志 | 引擎直接写本代文件，不依赖管理端输出管道 | M3 固定离线容量与保留边界，当前没有硬容量保证 |
| 身份未落盘 | 核验唯一候选；无法确定时保留未知并禁止重复派生 | M2 完整持久化恢复与幂等，不以再次创建掩盖残留 |

Ubuntu 实验使用独立 systemd 单元和私有挂载隔离共享安装。这是测试措施，不代表正式产品已经要求 root 或 systemd；普通用户运行 Go 管理端的部署流程仍须验证。

## 资源、日志与就绪

- 区分服务器实际资源路径和发送给客户端的 addon 标识。跨机使用两端可解析的名称及匹配资源；分发由上层负责，核心不更新玩家文件。
- 当前引擎日志路径限制为 ASCII，可含空格；不支持时明确拒绝而不换目录。该限制不针对中文日志内容，也不等于所有中文资源路径都已判定不支持。
- 就绪依据本代、带时间和来源的组合证据，不能仅凭 ss_active 或端口监听。本次地图使用加载、Host activate、地图 command-ready 与进程存活的组合；其他地图需另行验证规则。真实客户端进房用于验收。
- 启动观察 120 秒、优雅停止 10 秒、强制后确认 5 秒作为可配置初值，依据是本轮启动耗时和亚秒级正常退出。它们不是任意环境的性能保证；未确认退出不释放端口、不派生下一代。
- 同号 TCP/UDP 均检查；动态回环监听和出站临时端口记录归属，不全部当成公网预约端口。预检后仍可能发生外部抢占。
- 同机共用安装时，gameinfo 的历史 Advertise 改动与安全客户端握手失败存在对照证据，但未做反向复验。不能推广为 A2S 协议或异地服务器影响玩家客户端；普通启动不改 gameinfo，兼容性由 M4 验证。

配置快照、清理重试、创建去重及中断恢复的阶段责任见 [路线图](roadmap.md)，实测依据见 [M0 报告](validation/m0.md)。

## M1 配置与记录

模板和本地协议 v1 见 [契约](local-api.md)。M1 只覆盖游戏端口；规范化模板与覆盖值持久化，不依赖原模板再次读取。实例/操作使用128位随机 ID，生成 cfg 名同时包含实例 ID 和运行代次；独占创建，不按端口或模板名判断归属。

记录集中保存在 data-dir/state.json；每代另存日志及生成 cfg 副本。写临时文件并同步后替换，完整故障窗口与磁盘持久化保证在 M2 验收。清理只删除路径、归属和内容指纹均匹配的生成 cfg，不递归删除资源。清理失败保持待处理记录，重试不能派生进程。

Windows 端口预检显式设置 SO_EXCLUSIVEADDRUSE：普通通配监听无法可靠拒绝已有回环监听，已由实际失败测试确认。检查同时覆盖 TCP/UDP 和 IPv4/IPv6，仍不构成 OS 端口长期预约。

整个 data-dir 及 manager 子目录都要求同用户私有权限，避免绕过 IPC 改写状态。Windows 核验当前用户所有者及受保护继承 DACL；Linux 核验 owner 与0700。只为新目录创建权限，已有不安全目录拒绝且保持原权限。管理端关闭先停止接收、等待后台操作停止写入，再释放 data-dir 锁；专服不因管理端退出而被终止。

首次持久化错误后拒绝新变更及后续保存，查询暴露 IO_ERROR/persist，不能把未保存的回收或操作报告成成功。完整恢复与磁盘故障流程在 M2/M3 验收。停止期间已完成的输入文件清理单独记账，不对已清理的旧代次重新操作其可能被复用的 PID。

## M2 持久化与恢复

格式2采用初始化标记、完整性校验和严格关联校验，拒绝损坏及不兼容旧数据。持久化发布结果不确定时保留创建键和分配并拒绝后续变更，避免重试派生重复实例。每代保存启动尝试和绝对就绪截止时间；恢复只认领核验通过的原进程，不自动派生下一代。启动身份未保存时进行精确候选发现，多个候选或无法核验均拒绝认领。已确认退出的清理可按文件归属续办，不再使用旧PID控制进程。

实现与证据详见 [M2记录](validation/m2.md)。两平台已完成真实管理端退出/崩溃恢复和离线进房；整机重启仍未验证。以上不新增控制台通用命令接口，也不改变未来节点控制器的职责边界。

## CJ-07 附加端口冲突（裁决修复）

用户已确认：同协议、同端口、地址重叠的跨实例服务端点冲突撤销ready，但不自动杀房或换号；普通出站UDP只诊断，无法区分用途时明确报告不完整检查。

原生表只能可靠证明TCP处于listen；UDP本地端点不等于服务监听，Windows表尤其不提供远端用途。因此不按端口高低猜测UDP用途：主game端口UDP，以及与本进程TCP监听同端口且地址相交的UDP，按服务端点检查；其余UDP标为unclassified，不参与冲突。仅UDP的额外服务端口用途仍需运维核验，输出明确partial，不宣称已覆盖。该规则不新增模板字段或命令接口。

服务端点与其他未回收实例的主端口预约，以及其他经本轮重新核验身份和实际监听的服务端点比较。TCP/UDP分别比较；同地址族通配与具体地址相交，两个不同具体地址不相交；IPv6通配对IPv4的双栈属性仅凭现有端点不可确认，明确partial而不猜测冲突。绑定信息只表示本机观测，不表示公网可达。外部进程仍由主端口预检负责，附加检查范围为本管理端实例。
