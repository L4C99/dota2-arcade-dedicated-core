# 技术决策

## 工具链与实现边界

开发工具链为 Go 1.27.1，当前 Go 工具无第三方依赖。PowerShell/Python 用于 M0 实验，不是最终使用者的安装前提。M1 需将验证过的平台机制实现为 Go 适配并重新验收。

`m0-inspect` 只读取显式路径、解析链接并计算指纹，不启动引擎，也不验证写权限、资源冻结或任意 cfg 引用。静态检查成功不代表地图可加载。

## 进程、恢复与通信

| 方面 | 选型 / 约束 | 后续验证 |
| --- | --- | --- |
| Windows 身份 | 持有 OS 进程句柄后检查程序路径和精确创建时间 | 正式 Go 适配、重启后旧记录与身份冲突 |
| Windows 停止 | 独立辅助进程确认独占控制台后发送 quit；强制停止使用核验后的句柄 | 控制台不可用、完整子进程处理；不能用管理端关闭即杀游戏的 Job 选项 |
| Linux 身份与停止 | boot ID、启动 ticks、路径和 argv 核验；FIFO quit；pidfd 强制信号 | 正式 Go 启动/恢复适配；不退化为只按 PID 终止 |
| 本地传输 | Windows 当前用户 ACL 命名管道；Linux 私有目录 Unix socket，校验 peer UID | 跨用户拒绝、远程管道拒绝、端点抢占、超时及长路径 |
| 管理端离线日志 | 引擎直接写本代文件，不依赖管理端输出管道 | M3 固定离线容量与保留边界，当前没有硬容量保证 |
| 身份未落盘 | 核验唯一候选；无法确定时保留未知并禁止重复派生 | M2 完整持久化恢复与幂等，不以再次创建掩盖残留 |

Ubuntu 实验使用独立 systemd 单元和私有挂载隔离共享安装。这是测试措施，不代表正式产品已经要求 root 或 systemd；普通用户运行 Go 管理端的部署流程仍须验证。

## 资源、日志与就绪

- 区分服务器实际资源路径和发送给客户端的 addon 标识。跨机使用两端可解析的名称及匹配资源；分发由上层负责，核心不更新玩家文件。
- 当前引擎日志路径限制为 ASCII，可含空格；不支持时明确拒绝而不换目录。该限制不针对中文日志内容，也不等于所有中文资源路径都已判定不支持。
- 就绪依据本代、带时间和来源的组合证据，不能仅凭 ss_active 或端口监听。本次地图使用加载、Host activate、地图 command-ready 与进程存活的组合；其他地图需另行验证规则。真实客户端进房用于验收。
- 启动观察 120 秒、优雅停止 10 秒、强制后确认 5 秒作为可配置初值，依据是本轮启动耗时和亚秒级正常退出。它们不是任意环境的性能保证；未确认退出不释放端口、不派生下一代。
- 同号 TCP/UDP 均检查；动态回环监听和出站临时端口记录归属，不全部当成公网预约端口。预检后仍可能发生外部抢占。
- 同机共用安装时，gameinfo 的历史 Advertise 改动与安全客户端握手失败存在对照证据，但未做反向复验。不能推广为 A2S 协议或异地服务器影响玩家客户端；普通启动不改 gameinfo，兼容性由 M4 验证。

配置快照、清理重试、创建去重及中断恢复的阶段责任见 [路线图](roadmap.md)，实测依据见 [M0 报告](validation/m0.md)。
